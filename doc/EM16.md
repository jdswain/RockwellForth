em16 is a emulator for the L28 MCU.

It contains emulattion for other processors and systems.

It is written in C++. Much of the code is in header files, so when updating it is important to make clean before building.

/Users/jason/Development/1av/65/65Tools/em16 contains the source code.

It has a Makefile based build system. BUILD_BASE needs to be set to /Users/jason/Development/1av/65/65Tools.

It can load various formats, we are using ELF. ELF sets the load address and also start address for execution.

Use -t flag to start a trace log, this should be redirected with 2>/tmp/trace.log.

I use this command to start a test:

rm /tmp/trace.log; ../../65Tools/bin/em16 -t ForthDevelopment-L28 2>/tmp/trace.log

There are multiple ways to interact with the running code. We couldn't get the pty interface to work on macOS, so we are using direct terminal input.

## Input Line Termination

The Forth system (QUERY/EXPECT) requires CR (0x0D) as the line terminator, not LF (0x0A). When piping input from a file or printf, use \r not \n. With echo/printf use $'\r' or \r for each line end.

Example using printf to feed two Forth lines:

    printf ': foo 100 + ;\r1000 foo .\r' | ../../65Tools/bin/em16 ForthDevelopment-L28

## Redirecting stdin from a file

Use a file with CR-terminated lines and redirect stdin:

    ../../65Tools/bin/em16 ForthDevelopment-L28 < input.txt

The file must use CR (0x0D) at end of each line. LF-only files will cause EXPECT/QUERY to block indefinitely waiting for a line terminator.

## Running with a timeout on macOS

macOS does not ship a `timeout` command. Use a background kill pattern:

    (../../65Tools/bin/em16 -t ROM < input.txt > out.txt 2> trace.log) & \
    PID=$! && sleep 5 && kill $PID 2>/dev/null; wait $PID 2>/dev/null

## Trace output format

The -t flag writes CPU instruction traces to stderr. Each line has the format:

    BANK:LABEL OPCODE BYTES  MNEMONIC {BANK:RESOLVED_ADDR} E=N P=FLAGS A=HH[HH] X=HH[HH] Y=HH[HH] DP=HHHH SP=HH[HH] { RSTACK } DP= { DSTACK } DBR=HH I=HHHH W=HHHH

Where I= is the Forth instruction pointer and W= is a working register. UART receive events appear inline as [UART] recv $HH 'C'.
